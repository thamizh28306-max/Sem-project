1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
DataZen is an end-to-end full-stack property intelligence, neighborhood analysis,
and AI-assisted price estimation platform specifically engineered for the real
estate market in Chennai, Tamil Nadu, India.

Traditional property valuation in Chennai often relies on fragmented local broker
heuristics or opaque aggregator estimates that ignore micro-location factors such
as immediate proximity to metro rail lines, educational hubs, and civic amenities.
DataZen unifies three distinct architectural tiers:
  1. A reactive, high-performance web frontend with no complex build pipeline.
  2. A robust Node.js, Express, and TypeScript backend with caching, proxies,
     and PostgreSQL persistence via Prisma ORM.
  3. A Python and FastAPI-based machine learning microservice running an XGBoost
     regression model trained on Chennai real estate valuation dynamics.

In addition, DataZen features an IoT integration interface designed to ingest live
soil metrics (pH, moisture, NPK, temperature) from ESP32 microcontrollers, offering
land developers and buyers agricultural indicators for gardening and landscaping.

4. MODULE DETAILS & IMPLEMENTATION
--------------------------------------------------------------------------------

4.1 FRONTEND TIER (datazen/frontend/index.html)
- Architecture: Single-page application using React 18 and Babel directly via CDN.
  No npm build step, webpack, or Vite bundler required.
- Styling: Custom design system using CSS custom properties with a modern emerald
  and slate color palette, responsive grid layouts, animations, and custom scrollbars.
- Navigation: Multi-view architecture supporting:
    * Home (Hero section, analytics overview, platform benefits, how it works)
    * Properties (Browse, filter by locality/BHK/price, save listings, contact owner)
    * Predict Price (Dedicated standalone valuation calculator)
    * Map Explorer (Interactive GIS workspace)
    * Sell Property (Listing submission form with client-side validation)
- Leaflet GIS Integration:
    * Custom divIcon markers color-coded with distinct category emojis.
    * Dynamic radius circles (500m, 1 km, 2 km) centered on selected points.
    * Interactive popups showing estimated property value, range, and confidence.
- Tile Reliability & Fallback Mechanism:
    * <meta name="referrer" content="strict-origin-when-cross-origin"> header added
      to resolve OSM tile blocking when launched from localhost or static servers.
    * Tile layer event listener: if OpenStreetMap server triggers 3 tileerror
      events, the map automatically replaces the layer with CARTO basemaps
      (https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png).
- Autocomplete Search Box:
    * Debounced input (600 ms) to avoid sending excessive queries while typing.
    * In-memory cache map on the client side.
    * Dual-layer fallback: Queries Express proxy; if backend is unavailable,
      transparently falls back to direct browser-side Nominatim query.
- Full "Gather Information for Estimation" Panel:
    * Restored all 9 parameters required by the valuation model:
      Locality, Area (sq ft), BHK, Property Age, Floor Number, Distance to School,
      Distance to Metro, Parking availability, and Furnishing status.
    * Automatically synchronizes detected locality and computed school/metro
      distances when clicking on the map or selecting a search result.
    * Every field remains fully editable by the user for manual adjustment.

4.2 BACKEND TIER (datazen/backend)
- Runtime: Node.js with TypeScript and ts-node-dev for live reloading.
- API Design: RESTful endpoints mounted on /api.
- CORS Configuration: Permissive local configuration supporting requests from
  http://localhost:5173, http://localhost:5500, http://localhost:3000, 127.0.0.1,
  and null origins for local file testing.
- Nominatim Search Proxy (GET /api/places/search):
    * Accepts search term ?q=
    * Enforces OpenStreetMap usage policies by sending a compliant User-Agent
      header: "DataZen/1.0 (college project)".
    * Bounded bounding box specifically focused on the Chennai metropolitan region
      (79.9, 13.3, 80.4, 12.7).
    * Server-side in-memory caching (10-minute TTL).
    * Rate limiting throttle enforcing <= 1 request per second.
    * Returns HTTP 502 with structured error JSON on external network failures.
- Overpass API Surroundings Proxy (GET /api/places/nearby):
    * Accepts coordinates (?lat=, ?lng=) and search radius (?radius= in meters).
    * Generates an Overpass QL query covering 11 critical civic categories:
      Schools, Colleges/Universities, Hospitals, Clinics, Pharmacies,
      Supermarkets, Restaurants, Banks/ATMs, Parks, Bus Stations/Stops,
      and Metro/Subway stations.
    * Caching mechanism: In-memory cache keyed by latitude and longitude rounded
      to 3 decimal places (~100m accuracy) plus radius with a 10-minute TTL.
    * Calculates exact geodesic distances using the Haversine formula:
      d = 2R * asin(sqrt(sin^2(dlat/2) + cos(lat1)*cos(lat2)*sin^2(dlon/2)))
    * Structures response into counts per category, closest item per category,
      and overall shortest distance to school and metro transit.
- Property Listings Route (/api/listings):
    * Full CRUD integration backed by PostgreSQL through Prisma ORM.
    * Filtering by property type, locality, BHK count, and price boundaries.
    * User bookmarking (save/unsave) functionality.
- Authentication Route (/api/auth):
    * User registration with password hashing via bcryptjs (salt rounds = 10).
    * Secure login issuing signed JSON Web Tokens (JWT).
    * /me endpoint for token verification on browser reload.
- Soil Sensor Route (/api/soil-data):
    * Ingestion route for IoT microcontrollers to upload sensor batches.
    * Read routes providing historical readings for land and plot listings.

4.3 MACHINE LEARNING TIER (datazen/ml-service)
- Framework: Python 3.10+, FastAPI, Uvicorn, Pydantic, Scikit-learn, XGBoost.
- Training Pipeline (train.py):
    * Generates 3,000 synthetic Chennai real estate records based on authentic
      market distribution data across 8 major localities:
      Anna Nagar, Velachery, OMR, Adyar, Tambaram, Porur, T Nagar, Chrompet.
    * Incorporates baseline square-foot rates:
      Adyar: ₹9,500 | T Nagar: ₹8,800 | Anna Nagar: ₹8,500 | Velachery: ₹7,200
      OMR: ₹6,800   | Porur: ₹6,000   | Chrompet: ₹5,500   | Tambaram: ₹5,200
    * Features trained:
      1. locality (categorical, encoded via LabelEncoder)
      2. area_sqft (continuous numeric)
      3. bhk (integer, 1 to 4)
      4. age_years (integer, 0 to 30)
      5. floor (integer, 0 to 20)
      6. parking (binary: 0 or 1)
      7. school_dist_km (float, 0.2 to 5.0)
      8. metro_dist_km (float, 0.5 to 10.0)
      9. furnished (ordinal: 0=unfurnished, 1=semi, 2=fully)
    * Model: XGBRegressor(n_estimators=150, max_depth=5, learning_rate=0.08).
    * Exported artifact: model.pkl containing the model and fitted LabelEncoder.
- Inference Microservice (main.py):
    * POST /predict accepts PropertyInput schema with strict validation.
    * Encodes locality, computes model prediction, and derives valuation metrics:
      predicted_price, price_per_sqft, range_low (-8%), range_high (+8%),
      confidence score (82%), and detailed impact factors.


5. DATA MODEL & SCHEMA (PRISMA ORM)
--------------------------------------------------------------------------------
The relational database utilizes PostgreSQL with the following schema:

- User:
    id (UUID, PK), email (unique), password (hash), name, phone, createdAt, updatedAt
    Relations: listings (Listing[]), saved (SavedListing[])

- Listing:
    id (UUID, PK), title, locality, type (sale/rent/plot), bhk, sqft, price,
    age, floor, parking (Boolean), furnished, description, lat, lng,
    userId (FK -> User), createdAt, updatedAt
    Relations: user (User), savedBy (SavedListing[]), soilReadings (SoilReading[])

- SavedListing:
    id (UUID, PK), userId (FK -> User), listingId (FK -> Listing), createdAt
    Unique constraint: [userId, listingId]

- SoilReading:
    id (UUID, PK), ph, moisture, nitrogen, phosphorus, potassium, temperature,
    listingId (FK -> Listing, optional), deviceId, createdAt


6. API ENDPOINT SPECIFICATIONS
--------------------------------------------------------------------------------

BACKEND ENDPOINTS (PORT 3000):
  GET  /health
       Returns system operational status and timestamp.

  POST /api/auth/register
       Body: { name, email, password, phone? }
       Returns: User record and JWT access token.

  POST /api/auth/login
       Body: { email, password }
       Returns: User profile and JWT token.

  GET  /api/auth/me
       Header: Authorization: Bearer <token>
       Returns: Current user credentials.

  GET  /api/listings
       Query params: type, locality, bhk, minPrice, maxPrice
       Returns: Filtered array of property listings.

  POST /api/listings
       Header: Authorization: Bearer <token>
       Body: { title, locality, type, bhk, sqft, price, age, floor, parking, ... }
       Returns: Newly created listing record.

  GET  /api/places/search?q=<query>
       Query: Search string (e.g., "Tambaram", "T Nagar")
       Returns: Array of up to 5 matching geographic results with lat, lng, display_name.

  GET  /api/places/nearby?lat=<lat>&lng=<lng>&radius=<meters>
       Query: Center coordinate and radius in meters (500, 1000, 2000).
       Returns: Clean JSON object containing:
         - total_count: Total amenities located
         - counts: Object with item count per category
         - nearest: Object with closest place name and distance per category
         - school_dist_km: Nearest school in km
         - metro_dist_km: Nearest railway/metro station in km
         - places: Array of all individual amenities with lat, lng, and distance

  POST /api/predict
       Body: Full 9 property parameters.
       Returns: Valuation estimate from Python ML service or heuristic fallback.

ML SERVICE ENDPOINTS (PORT 8000):
  GET  /health
       Returns model name, version, and supported locality list.

  POST /predict
       Body: { locality, area_sqft, bhk, age_years, floor, parking,
               school_dist_km, metro_dist_km, furnished }
       Returns: { predicted_price, price_per_sqft, range_low, range_high,
                  confidence, locality, factors }


7. OSM USAGE POLICIES & COMPLIANCE
--------------------------------------------------------------------------------
OpenStreetMap (OSM), Nominatim, and Overpass APIs operate on free community
infrastructure that requires strict adherence to usage guidelines:
  1. Referer Header: Fixed by adding the strict-origin-when-cross-origin meta tag,
     allowing tile servers to recognize request provenance.
  2. User-Agent Identification: Nominatim proxy sets a clear User-Agent header:
     "DataZen/1.0 (college project)", preventing silent blocking.
  3. Throttling: Both Nominatim and Overpass proxies enforce a minimum 1.0 second
     delay between requests, preventing high-frequency bursts.
  4. Server-Side Caching: Both search and nearby queries are cached in memory for
     10 minutes, eliminating redundant calls for the same location.
  5. Client-Side Debouncing: Search keystrokes are debounced by 600 ms, preventing
     per-character network queries.
  6. CARTO Basemap Fallback: If OSM tile servers experience connectivity issues,
     the map seamlessly switches to CARTO basemaps.
